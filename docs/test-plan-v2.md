# CoWallet v2 首批真机用例规划

原则：一个用例 = 一个起始状态 + 一条主路径 + 一组明确断言；只读/可逆的探索与不可逆动作分开写。

## 0. 开始前需要确认的信息

| 项 | 说明 | 当前状态 |
| --- | --- | --- |
| 被测版本 | v2 的 Android APK / iOS 构建号 | 未提供 |
| 包名 / bundle id | 默认沿用 `com.cowallet.app` | 待确认是否变更 |
| 后端环境 | dev / staging / prod 的 API 地址；是否可用测试网与测试资金 | 待确认 |
| 测试账号 | 可复用的注册邮箱 / 恢复邮箱，是否为临时账号 | 待确认 |
| 用户状态 | 每个用例跑之前设备处于 fresh-install / email-registered-no-wallet / wallet-ready | 由 T02 判定 |

## 1. 用户状态模型（用例前置条件）

| 状态 | 特征 | 典型用例 |
| --- | --- | --- |
| `fresh-install` | 未注册未登录，只有注册/登录/恢复入口 | T03、T04 |
| `email-registered-no-wallet` | 身份存在但钱包不可用 | T04 后续、T05 |
| `wallet-ready` | 资产、AI 会话、转账入口可见 | T06 之后全部 |

状态不同，同一页面表现就不同。**不要**在没确认起始状态的情况下把差异报成缺陷。

## 2. 首批用例

风险等级：🟢 只读探索｜🟡 可逆但有状态变化｜🔴 不可逆（默认停在边界之前）

| ID | 用例 | 平台 | 前置状态 | 风险 | 断言要点 |
| --- | --- | --- | --- | --- | --- |
| T01 | 启动冒烟（已实现） | 双端 | 任意 | 🟢 | 首屏非空白；能读到 App 文案；设备与版本信息入档 |
| T02 | 用户状态识别 | 双端 | 任意 | 🟢 | 输出状态 + 依据文案；与人工观察一致 |
| T03 | 未登录入口覆盖 | 双端 | fresh-install | 🟢 | 注册/登录/恢复入口可见；不进入需要身份的内部页 |
| T04 | 邮箱注册 + OTP | 双端 | fresh-install | 🟡 | 发送验证码、错误码提示、成功进入下一步；OTP 输入支持人工介入 |
| T05 | 恢复钱包 + OTP | 双端 | fresh-install | 🟡 | 恢复入口、备份方式选择、恢复后状态；停在签名/密钥相关页之前 |
| T06 | 登录后首页与导航 | 双端 | wallet-ready | 🟢 | 首页关键模块与底部导航可达；tab 切换后状态正确 |
| T07 | AI 对话安全性 | 双端 | wallet-ready | 🟢 | 只读问答可答；模糊/危险提示词给出澄清或拒绝；不自动执行转账/冻结 |
| T08 | 设置与安全项 | 双端 | wallet-ready | 🟢 | 安全相关条目可见；点开只读，停在执行动作前 |
| T09 | 收款地址页 | 双端 | wallet-ready | 🟢 | 地址/二维码可见；网络提示是否充分（历史问题点） |
| T10 | 资产与余额 | 双端 | wallet-ready | 🟢 | 资产列表、链名、空状态、刷新行为 |
| T11 | 转账草稿 | 双端 | wallet-ready | 🔴 | 走到确认页即停；核对链、token、金额、收款地址展示 |
| T12 | 兑换草稿 | 双端 | wallet-ready | 🔴 | 走到确认卡即停；报价、decimals、滑点、失败态文案 |
| T13 | 滚动地图（首页/钱包/设置） | 双端 | wallet-ready | 🟢 | 记录顶部/中部/底部；列出因滚动或定位限制不可达的条目 |
| T14 | 权限与系统弹窗 | 双端 | wallet-ready | 🟡 | 相机/麦克风/通知弹窗出现时的允许/拒绝路径 |
| T15 | 后台切换与聊天持久化 | 双端 | wallet-ready | 🟢 | 切后台再回来，会话与结果卡是否还在 |

## 3. 执行边界

以下动作默认**只走到边界之前**，并在报告里留下证据：真实转账、兑换提交、授权、签名、导出/查看助记词或私钥、删除账号、紧急冻结。

需要真正执行时，必须当次明确授权，并同时满足：`.env` 里 `MANUAL_CONFIRM_REAL_TRANSFER=true`、`MAX_TEST_TRANSFER_USD` 设了合理上限、收款地址在 `TEST_SAFE_EVM_RECEIVER` 白名单内、确认页上的链/token/金额/地址与预期完全一致。

`../cowallet/blackbox-device-tests/scripts/` 下已有按旅程拆分的成熟脚本，移植优先级从高到低：

| v1 脚本 | 对应本规划 |
| --- | --- |

| `t02_detect_user_state_ios.ts` | T02 |
| `t03_unauthenticated_exploration_ios.ts` | T03 |
| `t04_signup_email_otp_*.ts` / `t05_recover_email_otp_*.ts` | T04 / T05 |
| `t06`–`t17`（首页、AI 安全、设置、发现、转账草稿、兑换草稿、DeFi、资产、收款、权限、风险边界） | T06–T14 |
| `t20`–`t22`（滚动地图） | T13 |

移植时要做的适配：`rootDir` / `.env` 路径、`start-wda.sh` 相对路径、包名与版本号。业务断言逻辑尽量保持，避免为了"跑通"而放松期望。

## 5. 报告与证据

- 每次运行产物：`reports/<时间戳>-<用例名>/`（`summary.json` + Midscene HTML 报告 + 截图）。
- 需要追踪的问题：整理到 `findings/`，关键截图放 `findings/assets/<run-name>/`。
- 缺陷报告至少包含：设备型号与系统版本、App 版本/构建号、后端环境、起始用户状态、实际结果、预期结果、复现步骤、截图路径。
