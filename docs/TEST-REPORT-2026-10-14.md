## 1. 报告概述

本次测试对 **CoWallet v2**（AI 原生 MPC 加密钱包）在 iOS 真机上进行了黑盒回归与探索测试，覆盖三个用户状态（fresh-install → email-registered-no-wallet → wallet-ready）下的主要用户旅程。目标：

- 回归验证《Cowallet v2 测试》文档中的既有问题（序号 1–8）在真机上的表现；
- 探索发现新的真机问题（序号 9–16）；
- 对不可逆动作（真实转账、签名、密钥导出、账号删除、冻结等）**默认停在执行边界之前**，仅当次明确授权才执行真实转账。

**方法与约束**

- 一个用例 = 一个起始状态 + 一条主路径 + 一组明确断言；用例脚本 `scripts/t01–t29`。
- 滚动页面做顶部/中部/底部滚动地图并记录不可达条目。

## 6. 重点结论

### 6.1 已验收（回归通过）

- **Issue 1（收款提示）**：真实入账 0.002 ETH 后，首页右上角铃铛出现红点角标，站内通知中心显示「收到钱了 — 收到 0.002 ETH（Ethereum）」。站内通知机制存在；但**锁屏/后台无 PUSH**，已另立 Issue 16。
- **Issue 2（第三片备份）**：设置 → 密钥检查 → 三份钥匙 →「现在花 30 秒测一下」，输入恢复密码后第 3 份·你保管由「尚未验证」变为「✓ 已验证」，显示「上次测试：今天，通过」。备份验证链路可用。
- **Issue 4（分片表述）**：设置卡（第 1 份·手机 / 第 2 份·服务器 / 第 3 份·你保管）与 AI 回答（手机份 / 服务器份 / 你自己保管的备份）位置一一对应，AI 明确承认服务器分片，历史矛盾表述未再出现。
- **Issue 16（收款 PUSH，新确认）**：真实外部转入 +0.0005 ETH（链上 0.0034777 → 0.0039777 ETH）后，App 后台化 + 锁屏/通知中心**无任何资金到账推送**（仅 TestFlight 更新通知）；重新打开 App 停在后台前所在页，站内铃铛角标与通知中心正常。源码佐证：`push_service.dart` PushType 枚举无「收款」类型，`push.rs` 仅 `mpc_sign_request` 发 push。

### 6.2 部分通过

- **Issue 3（轮换密钥）**：**结论更正**——v2 **存在**独立密钥轮换入口（设置 → 密钥安全 → 「轮换密钥分片（上次轮换: 从未）」），轮换页「换一套新钥匙」说明完整：手机/服务器/备份三份全换新、钱包地址不变、给新 24 词旧作废、Face ID 双确认、反诈提示，按钮「开始换钥匙」（执行边界，未点）/「先不换」。此前「v2 无独立轮换入口」的判断有误，已更正。**实际执行换钥匙未授权测试**（不可逆）；AI「保护这台手机」not_applicable 属 issue 15 独立问题。
- **Issue 5（ETH 转账）**：用户授权的一笔真实转账（0.0005 ETH → 白名单地址）全链路成功（确认卡金额/手续费/网络符合预期，Face ID 由真人确认，链上 0 区块确认）。此前一次失败为公共 RPC 瞬态返回 0，非 App 缺陷；建议复测确认稳定性。

### 6.3 待处理 / 待产品决策

- **6/7/8（Enclave 代码审查）**：属代码/架构问题，回归方式为修复评审与部署验证，非真机用例。
- **14（确认卡地址）**：T26 复测显示**已知收款地址已在卡上完整显示**（+ 复制按钮 +「√ 以前转过」），仅首次转账的未知地址仍走「尾 4 字符核对」交互。建议产品确认未知地址场景是否也显示完整地址。
- **15（AI 安全保护 UX）**：AI 提供「旧手机被人碰过，想保护这台手机」选项，选择后返回「无法生成计划 · not_applicable」且无原因/替代路径，对安全敏感场景的信任有负面影响。
- **9–13（新增中低优先）**：占位运营主体、引导进度持久化、换邮箱返回丢上下文、OTP 限流提示链路、键盘遮挡保存备份按钮，均已留证，等待排期。

## 7. 风险与建议

1. **收款无 PUSH（Issue 16）**：用户在锁屏/后台无法感知到账，是钱包类产品体验缺口，建议尽快支持「收款到账」推送类型（服务端 + 客户端枚举 + 通知权限申请）。
2. **AI 安全动作 UX（Issue 15）**：安全敏感入口给出「不可用」应提前过滤或给出原因与替代路径，避免死胡同。
3. **转账地址核对（Issue 14）**：建议确认卡对所有地址（含首次）都展示完整地址，降低转错风险。
4. **测试稳定性**：公共 RPC 偶发归零建议接入稳定 RPC/索引器；TestFlight 自动更新会中途改变 build，正式验收前应锁定构建版本。
5. **代码审查项 6–8**：与资金/签名安全相关，建议优先修复并做回归评审。

## 8. 遗留事项

- 陌生会话「帮我转 0.01 ETH 给小明」在语音测试混乱期间自动产生（真人未确认发起），待核实。
- 语音「查余额」异常进入兑换流程仅复现一次、上下文被污染，已暂停专项（用户决定先跳过语音测试）。
- 语言切换测试按用户要求跳过。
- 建议后续轮次：Issue 5 转账稳定性复测、Issue 3/15 收尾决策、Android 真机覆盖。
